## Changes in 1.5.5

- Bound the renderer status probe with the existing 750 ms observation deadline. An unanswered heartbeat previously held the durable run queue indefinitely, preventing Stop and therefore Restart. Regression: a never-resolving renderer releases the queue, Stop releases the lease, and a new run can start with the saved profile.
- Coalesce timer/alarm recovery wakeups per run before reading storage. Rearm a newer due attempt if its wakeup arrives while the previous command is still finishing; Stop and submit locks remain authoritative. This addresses a stranded third retry observed during the repeated browser test.
- Preserve the original URL for standalone runs, allowing their bounded recovery to open a safe GET as managed runs already do.
- Recognize the Vietnamese/Chinese custom acknowledgement seen on the live form, with no question/navigation controls and no page-health error. This confirms submission of the Google form; it does not confirm allocation of an exam slot.
- Watch a response-only document for late acknowledgement for at most 30 seconds after document replacement. This observes DOM changes and never clicks Submit or reloads a POST.
- Reattach read-only inspection when focusing the existing, same-run response document after an extension update.
- Identify the same form on `/closedform`, classify its Vietnamese closure text, and prohibit using that route as a new Start URL.
- Inspect CAPTCHA/account/error redirects even after the send reservation. Preserve the send lock and report the actual blocking reason.
- Explain the Restart lock on the manager row and put submission review at the top of details. Explicitly verified unsent old runs display their resolved status; the old run's submit flag remains intact.
